# BrandBuilder approval-to-publish acceptance worksheet — independent draft

Public sources inspected 3 October 2026: https://fg-uk.com/products/brandbuilder/ and https://fg-uk.com/tech/

BrandBuilder publicly describes a human approval gate, connected social publishing, brand/role workspace scope and an Analyst agent feeding learning into later campaigns. These boundaries justify a release acceptance conversation; none establishes an actual product defect.

| Boundary | Hostile fixture | Expected acceptance proof |
|---|---|---|
| Approval binding | Approved content changes before publish | Approval applies only to the reviewed content/version; changes require review. |
| Brand isolation | Asset or channel belongs to another workspace | No cross-brand publish or disclosure; explicit ownership binding. |
| Duplicate effects | Publish response times out and worker retries | Reconcile uncertain effect before retry; one durable channel receipt. |
| Revocation | Channel permission revoked after approval | Closed failure and operator-visible recovery; no authority widening. |
| Evidence loop | Analyst uses stale or partial campaign metrics | Source/window/coverage attached; unknown performance remains unknown. |
| Claims | Generated copy contains unsupported quantified outcome | Claim withheld or sent to human evidence review. |

The Group contact page invites partnership/procurement enquiries. A bounded independent release-test supplier proposal should name BrandBuilder and this scope. It must not imply access to private product internals or permission to run tests against production.
