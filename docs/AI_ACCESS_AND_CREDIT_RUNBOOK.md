# UberBond AI Access, Credits, and Free-Tier Runbook

Reference date: 2026-08-21
Policy: ai-access-opportunity-registry-1.0.0; universe coverage: ai-access-opportunity-universe-2.0.0
Truth boundary: this catalog proves only that an official provider route was documented and recorded. It does not prove Mohamed is eligible, that an application was approved, that a key was issued, that credits were granted, or that UberBond has revenue.

## What was added

The catalog is now a 55-route, multi-family universe covering student access, startup/cloud credits, model-provider programs, GPU/inference, research, open source, regional education, partner benefits, and coding tools. The family map is explicit and testable; it is designed for continuous ingestion, not a claim that every internet promotion has been discovered.

UberBond now has one governed access catalog connected to the existing opportunity-registry policy rather than a second commercial opportunity database.

The catalog stores:

- provider and official URL;
- last verification date and published expiry/closure;
- region or institution gate;
- eligibility requirements;
- value description with evidence classification;
- privacy/data risk;
- stackability and one-per-person notes;
- safe preparation actions;
- owner-only actions;
- zero-effect ledger;
- model-router tags.

Every record is VERIFIED_FACT only for the existence/description of the provider-published route. Eligibility, approval, credit issuance, payment, and production use remain OWNER_REVIEW_REQUIRED or APPLICATION_REQUIRED.

## What the system may do automatically

- store and version the catalog;
- verify that every record has an official HTTPS source, date, status, zero-effect ledger, and explicit owner gate;
- compare routes without claiming eligibility;
- produce an owner-action queue;
- prepare factual application packets from already-proven facts;
- create provider adapter contracts and no-op model-routing plans;
- run synthetic benchmarks with redacted fixtures;
- retire records when a published expiry or closure is known;
- record provider responses only when the owner supplies them.

## What the system must never do automatically

- fake a US location, institution, student status, startup, investor, research role, or nonprofit status;
- use VPNs or false documents to evade an eligibility gate;
- create multiple accounts or identities to farm a benefit;
- buy, share, sell, or borrow accounts;
- submit an application requiring an attestation, signature, KYC, ethics approval, or payment;
- create API keys, store secrets, accept billing, or enable overage without owner authorization;
- send provider emails, forms, or outreach;
- put unredacted customer secrets on a free tier whose terms allow provider improvement/training;
- call a listed credit granted until the provider receipt is recorded;
- count access or credits as UberBond revenue.

## Recommended owner queue

1. Verify genuine student status once through GitHub Education and Azure for Students if desired.
2. Check the official Google Egypt plan page and current Google student page; the US student offer is not an Egypt loophole.
3. Choose only the free API routes needed for a benchmark and create keys personally.
4. If UberBond has a genuine startup profile, submit at most one truthful application per provider for the appropriate startup tier.
5. Review billing caps, renewal, expiry, data handling, and one-per-person rules before accepting.
6. Give UberBond only the minimum credentials needed for a shadow benchmark; keep production and outbound credentials blocked.
7. Report provider receipts back to the canonical registry; the system can then update status with evidence.

## Router policy

- deterministic code first;
- free/low-cost providers only for redacted or synthetic, reversible tasks;
- provider attribution and quota in every evaluation receipt;
- no free-tier provider receives customer secrets by default;
- customer-facing or consequential work requires V9 authorization and an approved provider;
- model credits are a cost input, not a business outcome.
