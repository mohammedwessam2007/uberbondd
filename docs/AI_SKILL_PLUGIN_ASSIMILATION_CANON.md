# UberBond AI Skill & Plugin Assimilation Canon

## Purpose

UberBond may learn from and use external agent skills, Claude Code plugins, MCP servers, model gateways, memory systems, context compressors, security agents, browser/research tools, and similar capability packages. They are suppliers beneath UberBond, never replacement brains and never new canonical truth systems.

North star: `risk-adjusted cleared contribution profit / founder minute`.

This canon exists so GPT-5.6 Sol, Claude Code / Opus Max, Mission Control, and bounded UberBond AI employees can share one durable policy for discovering, evaluating, installing, invoking, learning from, and retiring external capabilities.

## Constitutional rule

External capability never creates authority.

A plugin, skill, model gateway, memory engine, security scanner, web-research CLI, hook, MCP server, or autonomous agent may increase what a worker can do. It may not grant itself permission to contact customers, scrape prohibited surfaces, bypass access controls, use private cookies, spend money, alter credentials/DNS, deploy production, move money, submit KYC, mutate customer systems, or promote synthetic output into commercial truth.

Current repository canon and durable external receipts outrank every plugin's memory, summary, recommendation, score, or model output.

## Assimilation loop

`discover -> verify source/license -> classify mechanism -> dedupe against UberBond -> threat/effect review -> choose smallest useful integration -> sandbox -> hostile test -> register -> expose to eligible workers -> observe outcomes -> improve/replace/revoke`

Do not vendor an entire external platform merely because it is popular. Prefer a project-local skill, provider-neutral adapter, read-only recommender, MCP boundary, isolated CLI, or mechanism abstraction.

## Capability classes

### A. CANONICAL_METHOD
A methodology or read-only skill that can be adopted directly as a working discipline. It does not become a truth source.

### B. PROJECT_SKILL
A skill package that may be installed project-locally and invoked by eligible workers. Skill instructions remain subordinate to `AGENTS.md`, `UBERBOND_CANON.md`, this canon, and current authority gates.

### C. OPTIONAL_RUNTIME
A local service, proxy, CLI, or plugin that changes execution behavior, context, routing, or persistence. It must remain replaceable, isolated, measurable, and reversible.

### D. EXTERNAL_ADAPTER
A provider/tool integration that should sit behind an UberBond contract rather than become an internal truth store.

### E. REFERENCE_ONLY
Useful mechanism research, but not eligible for automatic installation or code reuse until license/security/effect review clears it.

## Owner-provided acquisition set — 2026-08-30

Machine-readable companion: `artifacts/external-skill-plugin-registry.json`.

### Find Skills — `vercel-labs/skills`, `find-skills`

Disposition: **PROJECT_SKILL / capability-discovery front end**.

Use it when a worker identifies a missing capability or specialized task that may already exist in the open skills ecosystem. Discovery output feeds UberBond's existing Automation Capability Acquisition Loop; it never authorizes installation by popularity alone.

Preferred use:
- search for candidate skills;
- record source, version/ref, license, install count/reputation signals, and claimed capability;
- dedupe against current UberBond modules and already-approved skills;
- pass candidates through the same evidence/license/effect review as repositories.

### Anthropic Claude Code Setup

Disposition: **CANONICAL_METHOD / read-only project auditor**.

This official Anthropic plugin analyzes a codebase and recommends MCP servers, skills, hooks, subagents, and slash commands. It is explicitly read-only. Use it periodically as a capability-gap/audit supplier, then reconcile every recommendation against UberBond's canonical capability registry before adopting anything.

It must not be treated as permission to add a second workflow engine, second CRM, second memory truth system, or uncontrolled hook.

### Task Observer — `rebelytics/one-skill-to-rule-them-all`

Disposition: **PROJECT_SKILL / skill-learning observer**.

Use it to capture:
- owner corrections and steering;
- repeated manual work that suggests a missing skill;
- observed weaknesses in existing skills;
- cross-cutting principles that should raise the skill quality floor.

Task Observer's own contract is recommendation-first rather than silent mutation. UberBond preserves that property: observations may generate proposed skill updates, but canonical skills/prompts are changed only through normal diff/review/test/merge evidence.

Store project observations under a durable, non-secret workspace such as `artifacts/skill-observations/` or an equivalent project-local path. Never log secrets, raw private customer data, credentials, or unnecessary PII.

### Claude-Mem — `thedotmack/claude-mem`

Disposition: **OPTIONAL_RUNTIME / local session-memory cache beneath repository memory**.

Claude-Mem can preserve/compress context across Claude Code sessions. It is useful for developer productivity, but UberBond already has canonical repository-native memory. Therefore:
- Claude-Mem memory is advisory/local working memory;
- `npm run brain`, `UBERBOND_BOOTSTRAP.json`, Master Memory, current state/readiness, durable handoffs, current `main`, and external receipts always outrank it;
- no Claude-Mem summary may silently change commercial truth or historical canon;
- contradictory memory must be surfaced, not auto-resolved in favor of the plugin;
- secrets/private data must not be promoted into committed repository memory.

Use Claude-Mem to reduce re-reading and session amnesia, not to create a second company brain.

### Headroom — `headroomlabs-ai/headroom`

Disposition: **OPTIONAL_RUNTIME / context-compression and retrieval supplier**.

Headroom may compress large tool outputs, logs, JSON, search results, and other high-volume context. Use it where savings are measurable and reversibility/retrieval remains available.

Never allow lossy compression to become the sole evidence copy for:
- repository canon;
- exact diffs;
- payment/provider/customer receipts;
- legal/authority evidence;
- security findings;
- acceptance/delivery proof;
- contradiction records.

For authoritative material, preserve original bytes/hash/reference and treat compressed text as a navigation/working representation. Prefer explicit retrieval or passthrough when exactness matters.

### OmniRoute — `diegosouzapw/OmniRoute`

Disposition: **OPTIONAL_RUNTIME / model-gateway and fallback research supplier**.

OmniRoute provides a provider/model gateway, routing/fallback, MCP/A2A, and context/token optimization mechanisms. UberBond already has model-routing and provider-admission concepts, so OmniRoute must not become a second policy brain.

Eligible uses:
- isolated engineering/research sessions where provider routing is explicitly configured;
- benchmarking cost/latency/availability routing mechanisms;
- studying fallback and quota-aware routing patterns;
- optional execution supplier behind UberBond's model-routing/admission contracts.

Requirements:
- credentials stay outside the repository;
- provider/model identity must remain observable in receipts;
- routing changes may not widen tool/business authority;
- fallback may not silently downgrade evidence, privacy, safety, or model capability requirements;
- no "free provider" claim is treated as durable economics without current provider evidence.

### Strix — `usestrix/strix`

Disposition: **PROJECT_SKILL + OPTIONAL_RUNTIME / authorized security verification worker**.

Use Strix only against code, URLs, domains, systems, or environments UberBond owns or has explicit permission to test. Default scope is local/test/preview environments and repository-controlled targets.

Eligible roles:
- application security testing;
- proof-backed vulnerability discovery;
- remediation guidance;
- CI security validation;
- re-test after fixes.

Prohibited:
- scanning unrelated third parties;
- unauthorized exploitation;
- credential theft;
- persistence;
- destructive actions;
- using security findings to justify broader consequence authority.

Security findings remain evidence candidates that require verification before promotion into canonical defect truth.

### Agent Reach — `Panniantong/Agent-Reach`

Disposition: **EXTERNAL_ADAPTER / research and world-sensing supplier, high policy sensitivity**.

Agent Reach aggregates access paths for public/social/niche web sources. This can materially strengthen Prometheus/world sensing, competitor research, buyer-language research, software scouting, and opportunity discovery.

However, UberBond's source policy dominates Agent Reach's technical capability:
- public/authorized sources only;
- no CAPTCHA bypass, fingerprint spoofing, access-block evasion, or prohibited scraping;
- no private-account access or cookie/session use unless the owner has separately authorized that exact source/account and policy permits it;
- no inferred private contact information;
- respect platform terms, robots/access controls where applicable, privacy, rate limits, jurisdiction, and source provenance;
- a reachable page is not permission to harvest or contact people;
- preserve source URL/time/provenance and distinguish claims from verified facts.

Prefer read/search modes that do not require authentication. Treat channels with login, brittle scraping, or access-circumvention characteristics as disabled until separately reviewed.

## Shared worker protocol

Before using an external capability, a worker must determine:
1. `capability_id` and exact source/ref/version where practical;
2. why the canonical UberBond stack cannot already satisfy the task more safely/cheaply;
3. class: method, skill, optional runtime, adapter, or reference-only;
4. license/attribution obligations;
5. data scope and whether secrets/private data would transit the tool;
6. external-effect surface;
7. required authority;
8. sandbox/isolation level;
9. observable receipt or output identity;
10. rollback/revocation path;
11. expected founder-minute/economic benefit;
12. kill condition.

If these cannot be resolved, use `REVIEW_REQUIRED` or `REFERENCE_ONLY` rather than installing/activating blindly.

## Skill-learning law

UberBond should improve its skills continuously, but never by silent self-editing.

`session/work -> observation -> candidate lesson -> evidence/counterexample -> proposed skill diff -> review/tests -> merge -> versioned skill`

Owner corrections are high-value evidence about workflow quality, not automatic universal truths. A correction may be task-specific. The observer must separate local preference, project invariant, safety rule, and general reusable technique.

## Memory law

There is one canonical company memory hierarchy:

`current repository/executable truth -> durable external receipts -> repository canon/master memory/handoffs -> approved working summaries -> plugin/session memory`

External memory systems can accelerate recall but may never override higher layers.

## Context-compression law

Compression is an optimization, not evidence destruction.

For any material source, preserve enough information to recover or re-fetch the authoritative original. Do not make a compressed summary the only surviving representation of receipts, canon, source code needed for exact review, legal evidence, payment truth, or customer acceptance.

## Security-tool law

Security tools run with the least privilege and smallest target scope that answers the question. Default to local/test/preview. Any live target requires explicit ownership/authorization and a bounded test plan.

## Research-tool law

A tool that can reach a source is not automatically allowed to use it. Source access remains subject to law, privacy, platform terms, consent/authorization, source provenance, and UberBond's no-bypass rules.

## Runtime installation policy

Project-local, reversible installation is preferred over global mutation. Pin versions/refs when operationally practical. Do not commit secrets or cookies. Do not auto-start paid providers. Do not make a plugin required for core UberBond truth unless the company has a tested fallback and migration path.

A live Claude Code environment may install the approved project skills/plugins/runtimes from this registry after verifying current upstream installation instructions and dependency/security posture. Installation itself does not authorize network consequences beyond obtaining the package and its documented dependencies.

## Executive responsibilities

### GPT-5.6 Sol / Company Brain
- use Find Skills and the external registry as candidate-generation inputs when a capability gap appears;
- research current upstream status, license, security posture, and alternatives;
- evaluate commercial and founder-minute leverage;
- never recommend a tool merely for novelty;
- produce bounded implementation packets for missing capabilities.

### Claude Code / Opus Max / Software Factory
- load this canon at startup;
- use approved skills/tools where they improve implementation or verification;
- keep plugin/runtime state subordinate to repository truth;
- install project-local where possible;
- sandbox Strix and other high-power tools;
- verify exact effects and leave durable receipts;
- do not let plugin hooks bypass UberBond consequence controls.

### Mission Control / Integrator
- dedupe skills/plugins against current capabilities;
- reconcile conflicting memories/recommendations;
- verify source/version/license and runtime boundaries;
- revoke or downgrade integrations that become unsafe, stale, redundant, expensive, or economically inferior.

## Initial assimilation verdict

The owner-provided set is valuable, but not as eight always-on gods inside the machine.

- **Immediately adopt as durable methodology/candidate sources:** Find Skills, Claude Code Setup, Task Observer.
- **Prepare/allow as bounded optional developer runtimes:** Claude-Mem, Headroom, OmniRoute.
- **Prepare/allow as bounded verification/research capabilities:** Strix, Agent Reach.
- **Never allow any of them to replace:** UberBond canon, payment truth, authority/consent/suppression, distribution attribution, delivery/acceptance truth, or repository-native company memory.

That preserves the upside while preventing capability sprawl from eating the company brain.
