## New source layer

`src/apex-fresh-campaign.mjs` closes the gap between the existing sealed tournament and a scientifically fresh campaign.

It has three stages:

1. `prepareFreshApexCampaign`
   - freezes the complete architecture roster before holdout commitment;
   - freezes model + reasoning setting + transport class + exact pricing mode;
   - freezes topology, prompt contract, context policy, verifier policy and execution mode;
   - requires one incumbent and one or more challengers;
   - makes the frontier quality floor lexicographically dominant;
   - requires per-architecture spend ceilings and a total campaign spend ceiling.

2. `admitFreshCustodianManifest`
   - accepts only a sealed digest manifest, never raw prompts or plaintext answers;
   - binds it to an independent external custodian receipt;
   - requires the holdout commitment to occur after architecture freeze;
   - requires fresh generation for this campaign;
   - refuses previously evaluated items, derivations from evaluated items and legacy evidence reuse;
   - keeps raw holdouts outside the repository.

3. `assessFreshCampaignRuntimeReadiness`
   - requires observed live callability for every model + reasoning setting;
   - requires verified transport;
   - requires exact model and reasoning-setting identity;
   - requires exact pricing evidence for every frozen pricing mode;
   - cannot call providers, spend money or authorize execution.

## Wave 1 $10 experiment

Machine-readable contract:

`config/apex-frontier-quality-compression-campaign.json`

Hard total campaign cap:

`$10.00`

The four candidate architectures are:

### 1. Opus 5.5 MAX interactive baseline

Purpose: strongest expensive reference architecture.

Spend ceiling: `$3.00`

This baseline defines the frontier quality floor for Wave 1. `maxQualityDelta = 0`: a cheaper architecture does not win merely by being almost as good.

### 2. Same-model Opus 5.5 MAX deferred compression

Purpose: test whether the exact same frontier cognitive identity can be purchased more cheaply through deferred/batch execution plus cache-stable context.

Spend ceiling: `$2.00`

The model and reasoning setting remain Opus MAX. Only the execution/economic graph changes.

### 3. Opus + MiMo quality-compression swarm

Purpose: test whether one frontier orchestrator/final judge plus a large population of much cheaper strong workers can reproduce the baseline quality at lower total cost.

Spend ceiling: `$2.50`

Candidate worker hypothesis:

- MiMo-V2.6-Pro high-power reasoning workers;
- MiMo-V2.6-Flash mass exploration workers;
- Opus 5.5 MAX retains final semantic authority;
- Jev remains SHADOW_ONLY.

These Xiaomi candidates are discovery evidence only until exact transport, callability, reasoning-setting and pricing receipts exist.

### 4. Opus + heterogeneous efficiency swarm

Purpose: test whether diversity beats a single cheap-model population by reducing correlated errors.

Spend ceiling: `$2.50`

Candidate worker hypothesis:

- DeepSeek V4.1 Flash;
- Qwen3.8 Flash;
- GLM-5.3-Flash;
- Opus 5.5 MAX orchestrator/final judge;
- Jev SHADOW_ONLY.

Again, no discovery-only model may execute before exact runtime admission.
