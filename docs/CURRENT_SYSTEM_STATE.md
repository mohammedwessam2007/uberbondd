**119 of 254 `src` modules have no entry point at all** — not production, not an

behaves while proving nothing about whether anything can call it.

| | |
|---|---|

| Reachable only via an operator script | 9 |

That includes the whole commercial layer — lead scoring, outreach, prospect
intelligence, inbound sensing, causal attribution, fulfillment — and the whole
Claude engineering path.

Most of it is *correctly* unreachable: wiring outreach without an authorisation
path is how a system contacts someone by accident. But the decision has to be
written down, so every one of the 45 is classified in
`config/reachability-classification.json` with a named gate and a real reason,
and `tests/reachability-ratchet.test.mjs` fails when a new unclassified dead
module appears. Nothing remains in `NEEDS_TRIAGE`.

The gate itself used to be the weak point. `AWAITING_ACTIVATION` required only
that the `gate` field be truthy, so a probe setting
`gate: "TODO_FIGURE_THIS_OUT_LATER"` passed every ratchet test — which made
`AWAITING_ACTIVATION` a resting state reachable by typing anything. Gates are now
declared in a registry with what they block and what would release them, so
minting one is a reviewable edit rather than a string typed into one module.

This distinction cost three separate discoveries in one session: the mesh entry
point, the occurrence compiler, and the escalation kernel. All three were
implemented, tested, green, and dead.

## 3. What the architecture now guarantees

Each of these is a property with a test that fails when the property is removed.

**Authority never widens — in all three dimensions.** A child task carries every
constraint its parent carried, at any chain depth, including at the ceiling
where a silent truncation used to drop two. It also inherits every forbidden
action, and its token budget is capped at the parent's: a child asking for
500,000 tokens against a 40,000-token parent gets 40,000. Overflow refuses to
compile rather than trimming.

**A claim is not evidence.** A worker result claiming DONE must carry a
non-empty outcome, a supported truth table, and tests where it changed
artifacts, and may not answer with another task's identity. Below DONE the
contract is looser, so a research result still needs no test run.

**A zero-effect claim must be complete.** An omitted ledger key used to read as
zero, so `{}` scored the same as a signed zero. The canonical key set with real
numeric zeros is required; an invented counter is reported as an unknown effect
key rather than as a credential leak.

**One occurrence, one consequence.** A scheduled occurrence writes one STARTED
receipt and one TERMINAL receipt. Redelivery is refused. 800 occurrences with
every fifth delivered three times produce exactly 800 terminal receipts.

**A crash is written down.** A cycle that died between STARTED and TERMINAL used
to be invisible — not a failed tick, nothing at all — so a mesh crashing every
other cycle could still present an unbroken run. Abandoned cycles now block
certification until reconciled into recorded DEGRADED failures, and the
scheduler reconciles them at the top of each cycle.

**No run starves.** The scheduler scans oldest-touched first, so being served
moves a run out of the window and being ignored moves it in. With 260 active
runs against a 200-run scan cap, every run is served; previously 60 never were.

**A stalled run says so.** A bounded scan that comes back full no longer answers
with a stale snapshot. It reports `autonomy-run-snapshot-scan-saturated`.

**A known-bad route blocks qualification.** Scoring a contact zero is not the
same as blocking on it. `scoreLeadCandidate` names the route state — invalid,
suppressed, stale, needs-review, unverified — and an unstated verification
state is refused, because "we never checked" and "we checked and it is fine"
must not score the same (issue #99).

**The occurrence layer is reachable, not just implemented.** `compileScheduledAutonomyRun`
existed and nothing in production called it — a compiler nobody compiled with,
the same gap #88 recorded for the mesh. `AGENT_MESH_MISSION` declares one
recurring mission and the tick seeds it before pumping, idempotently: the same
occurrence finds its run, the next occurrence gets its own. A reachability
assertion is part of the test, because a green suite says nothing about whether
a module can be reached.

**Suppression dominates enrichment.** An unsubscribe is sticky and cannot be
outvoted by a later VALID check. Plus-tagged and dot-variant forms of a
suppressed address are the same mailbox. A complaint recorded as a risk flag
blocks as firmly as one recorded as a state.

**No model grants authority.** Prospect qualification scores nine weighted
dimensions with provenance and a deterministic policy decides. A model
assessment is capped at half weight, can never carry ICP fit, buyer-role fit or
reachability alone, and a model that includes a decision-shaped field gets the
prospect quarantined rather than that field ignored.

**One provider event is one payment.** Cleared revenue requires three witnesses
— an order, a classification receipt and a ledger row, all keyed on the same
provider event. The witness sets were deduped and the ledger rows were not, so
a $50 payment recorded twice reported $100 cleared. Rows dedupe by event now,
and a duplicate raises a contradiction rather than being quietly dropped.

**Revenue cannot be typed into existence.** A payment node's outcome id must
recompute as a digest of the commercial-outcome policy version and its own
provider event id, so a forger has to produce the receipt the compiler would
have produced rather than one merely shaped like it. Still forgeable by whoever
controls the provider event id; no longer forgeable from nothing.

**Evidence cannot launder its own provenance.** A declared evidence class is
clamped to what its source can support, so a search snippet cannot file itself
as first-party and outrank a company's own team page. The clamp is recorded,
not silent.

**A cleanup routine is not a delete primitive.** The sandbox destroyer removes
only workspaces this process actually created; a directory merely *named* like
a sandbox is refused.

**One secret vocabulary.** Six modules had six different credential regexes with
six different holes. There is one now, and durable receipts redact free text
rather than truncating it.

## 4. What is blocked, and by what

| Blocker | What it stops | What clears it |
|---|---|---|
| `SANDBOX_PROVISIONER_EXTERNAL_BLOCK` | Autonomous Claude engineering | An isolation attestation from whatever enforces the network boundary |
| No provider credential | Any real model call | One credential plus an authorised spend cap |
| No payment provider identity | Any cleared revenue | Owner completes onboarding and KYC |
| No `gmail.readonly` grant | Inbound sensing | Owner authorises readonly inbox access |
| No elapsed time | Multi-day founder-absence tiers | Days passing, with real cycles accumulating |
| No scheduler firing the tick | Every live tier | Activating `scripts/agent-mesh-tick.mjs` on a timer |
| No Playwright Chromium in this runner | Browser/interface verification | Install the pinned Chromium binary in a runner with CDN access, then rerun `npm run test:browser` |

The sandbox one is worth stating plainly: the provisioner does real work —
ephemeral workspace, pinned local clone with copied git objects, credential-free
child environment, git restricted to five subcommands with no shell — and then
refuses to sign a receipt for network isolation it cannot verify. A Node
process cannot make the production network unreachable to its own children.
Claiming otherwise in a receipt is exactly the self-attestation this codebase
exists to refuse.

## 5. Known bounds, not yet cured

**Snapshot scan ceiling — removed, not raised.** Four modules each held a
private `MAX_SCAN` and passed it straight through as `store.list({ limit })`.
That reads as a page size and behaves as a ceiling: `_listDirect` applies no
ordering unless asked, so rows arrive oldest-first and `limit: 2000` returns the
OLDEST 2000. Two probes against the real modules:

- 2100 filler snapshots then one new run: `listLatestAutonomyRuns` answered
  `ok: true, status: 'LISTED'` with the new run absent. Not a saturation error —
  a confident, complete-looking, wrong answer.
- 2100 filler selections then three runs served: the scheduler re-served 2 of
  those 3 immediately, because from inside the window they had never been
  served. The starvation bug the fairness ledger exists to prevent, returning at
  scale, silently.

`src/durable-audit-scan.mjs` folds rows into an accumulator as pages arrive, so
the walk runs to exhaustion at memory bounded by distinct keys rather than
history length. A walk that cannot finish fails closed: `SCAN_SATURATED` from
the listing, `FAIRNESS_LEDGER_UNREADABLE` from the scheduler. The scanner's
`MAX_PAGES` is a liveness guard, not a data ceiling — exceeding it is a refusal
with a reason code, never a truncated success.

**Real-PostgreSQL suites need serial execution.** Stable serially over three
consecutive runs; intermittently failing in parallel. The cause is
cross-file interference on a shared database, not the code under test. Encoded
in the npm script rather than left to memory.

**One SKU compiler, after two arrived.** #72 and #101 each shipped a
ServiceSKU compiler and an acceptance state machine within a day of each other,
both exporting `compileServiceSku`. Neither was reachable, so nothing in
production was affected, but a reader had no way to tell which one the system
meant. `src/service-sku.mjs` and `src/service-fulfillment.mjs` survive — they
are a connected chain and they model support, renewal, retention and churn.
Every invariant the superseded suites asserted is re-pinned against the
survivor in `tests/superseded-fulfillment-invariants.test.mjs`.

**Two ledger shapes, now bridged.** `externalEffectLedger` (8 keys) and
`businessEffectLedger` (7 keys) still answer different questions, but
`normalizeEffectLedger` maps both onto one canonical key set —
`businessSpendCents` onto `spendCents` — and refuses missing keys, unknown keys
and non-integer counters.

The scanner exemption stays deliberately loose, and there is a test explaining
why: an incomplete ledger is a counter with a missing field, not a credential.
Making the exemption strict flips `hasSecret({providerCalls: 0})` from false to
true and remislabels a missing counter as a leaked secret. Completeness is
enforced by `validResult` and `normalizeEffectLedger`, which name the actual
problem.

**Detection exists; delivery does not.** The system now assesses its own health
after every cycle from durable truth — silent scheduler, abandoned cycles, dead
letters, stalled and stranded runs, effect-ledger integrity — and persists an
owner action queue. A dimension the store cannot answer is reported unreadable
rather than as zero, because "nothing is wrong" and "we did not look" must not
be the same value.

**Escalation: decided, recorded, and still undelivered.** Two defects sat here.
The suppression the kernel was built with was never fed — ten ticks against one
unchanging condition wrote thirty durable rows for three real problems, which at
an hourly cadence is seventy-two duplicate pages a day about one fact. And
`transport: 'UNCONFIGURED'` was a literal with no transport concept behind it,
so a delivery that failed was indistinguishable from one never tried.

`src/operator-escalation-transport.mjs` is the transport half. It deliberately
ships no transport that reaches a human device: a `HUMAN_DEVICE` transport
without an owner authorization reference is refused outright rather than
registered and skipped. What it does provide is durable per-transport receipts,
three distinct outcomes where there was one (`UNCONFIGURED`, `DELIVERY_FAILED`,
`DELIVERY_UNKNOWN` — a transport that throws is unknown, never failed, because a
throw after the bytes left is not proof of non-delivery), and a CRITICAL
`OWNER_UNREACHABLE` escalation about the inability to escalate.

**Founder-absence readiness no longer ignores deliverability.** A proof
satisfying every dimension — 900 successful ticks over 31 days, zero
unauthorized effects, zero dead letters, zero abandoned cycles, every capability
`VERIFIED_LIVE` and externally verified — returned `KILIMANJARO_READY` at 100%
while nothing in the repository could reach a person. `ownerEscalationQueue` was
satisfiable by the queue existing. `undeliveredEscalations` is now a required
proof dimension, absent means refused rather than zero, and it is read from the
durable page ledger rather than accepted as an assertion.

**Nothing wakes a human yet.** That still needs a channel credential, which is
an owner action.

**A revoked approval used to arrive too late.** The final recheck before the
provider boundary re-read suppression, sender health, settings and the account
from the store, and evaluated *authority* from the in-memory campaign the batch
loop had loaded. Approval revoked in the database mid-batch produced
`ALLOW_LOCAL_PREPARATION` with zero deny reasons. Authority is now re-read from
durable storage on every evaluation and fails closed on every path where the
answer is not knowable; caps and country allowlists count as authority too,
because a stale ceiling authorizes volume the owner has taken back.

**Refunds were invisible to revenue truth.** `payments.mjs` classifies
`order_refunded` with `revenueSign: -1` and writes a negative ledger row;
`payment-renewal-truth.mjs` read only rows above zero. A $50 payment refunded in
full reported `providerClearedRevenue: $50.00`, `ok: true`, `contradictions: []`.
A reversal now needs the same three witnesses a payment needs, `PAYMENT_RETAINED`
is a separate stage from `CLEARED_PAYMENT`, and
`netProviderClearedRevenueCents` is the number a revenue claim has to use.

**Self-improvement could edit its own limits.** A well-formed change set with a
bland rationale and a passing verification command was ACCEPTED for
`agent-code-change-contract.mjs`, `deliverability-guard.mjs`,
`agent-autonomy-loop.mjs`, `cloud-agent-relay.mjs`, `secret-patterns.mjs`,
`payment-renewal-truth.mjs`, `operator-escalation.mjs`, the reachability
classification and its ratchet. Every one. A `SOVEREIGNTY_PREFIXES` tier now
makes those editable only by a person, with its own reason code so an operator
can tell "you tried to edit the build graph" from "you tried to edit your own
limits".
