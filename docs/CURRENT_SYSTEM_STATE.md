## 3. What the architecture now guarantees

Each of these is a property with a test that fails when the property is removed.

**Authority never widens.** A child task carries every constraint its parent
carried, at any chain depth, including at the constraint ceiling where a silent
truncation used to drop two of them. Overflow refuses to compile rather than
trimming.

**A claim is not evidence.** A worker result claiming DONE must carry a
non-empty outcome, a supported truth table, and tests where it changed
artifacts, and may not answer with another task's identity. Below DONE the
contract is looser, so a research result still needs no test run.

**A zero-effect claim must be complete.** An omitted ledger key used to read as
zero, so `{}` scored the same as a signed zero. The canonical key set with real
numeric zeros is required; an invented counter is reported as an unknown effect
key rather than as a credential leak.

**One occurrence, one consequence.** A scheduled occurrence writes one STARTED
receipt and one TERMINAL receipt. Redelivery is refused. 800 occurrences with
every fifth delivered three times produce exactly 800 terminal receipts.

**A crash is written down.** A cycle that died between STARTED and TERMINAL used
to be invisible — not a failed tick, nothing at all — so a mesh crashing every
other cycle could still present an unbroken run. Abandoned cycles now block
certification until reconciled into recorded DEGRADED failures, and the
scheduler reconciles them at the top of each cycle.

**No run starves.** The scheduler scans oldest-touched first, so being served
moves a run out of the window and being ignored moves it in. With 260 active
runs against a 200-run scan cap, every run is served; previously 60 never were.

**A stalled run says so.** A bounded scan that comes back full no longer answers
with a stale snapshot. It reports `autonomy-run-snapshot-scan-saturated`.

**Suppression dominates enrichment.** An unsubscribe is sticky and cannot be
outvoted by a later VALID check. Plus-tagged and dot-variant forms of a
suppressed address are the same mailbox. A complaint recorded as a risk flag
blocks as firmly as one recorded as a state.

**No model grants authority.** Prospect qualification scores nine weighted
dimensions with provenance and a deterministic policy decides. A model
assessment is capped at half weight, can never carry ICP fit, buyer-role fit or
reachability alone, and a model that includes a decision-shaped field gets the
prospect quarantined rather than that field ignored.

**One secret vocabulary.** Six modules had six different credential regexes with
six different holes. There is one now, and durable receipts redact free text
rather than truncating it.

## 4. What is blocked, and by what

| Blocker | What it stops | What clears it |
|---|---|---|
| `SANDBOX_PROVISIONER_EXTERNAL_BLOCK` | Autonomous Claude engineering | An isolation attestation from whatever enforces the network boundary |
| No provider credential | Any real model call | One credential plus an authorised spend cap |
| No payment provider identity | Any cleared revenue | Owner completes onboarding and KYC |
| No `gmail.readonly` grant | Inbound sensing | Owner authorises readonly inbox access |
| No elapsed time | Multi-day founder-absence tiers | Days passing, with real cycles accumulating |
| No scheduler firing the tick | Every live tier | Activating `scripts/agent-mesh-tick.mjs` on a timer |

The sandbox one is worth stating plainly: the provisioner does real work —
ephemeral workspace, pinned local clone with copied git objects, credential-free
child environment, git restricted to five subcommands with no shell — and then
refuses to sign a receipt for network isolation it cannot verify. A Node
process cannot make the production network unreachable to its own children.
Claiming otherwise in a receipt is exactly the self-attestation this codebase
exists to refuse.

## 5. Known bounds, not yet cured

**Snapshot scan ceiling.** Autonomy run reads pull a bounded window of 2000
audit rows. Past that the read refuses rather than going stale, which is the
important half — but it is a ceiling. Curing it needs per-run reads, and the
store's filters match top-level columns and cannot select on `detail.runId`.
That is a schema change, deliberately not done tonight.

**Real-PostgreSQL suites need serial execution.** Stable serially over three
consecutive runs; intermittently failing in parallel. The cause is
cross-file interference on a shared database, not the code under test. Encoded
in the npm script rather than left to memory.

**Two ledger shapes still exist.** `externalEffectLedger` (8 keys, provider
calls and cents) and `businessEffectLedger` (7 keys, business spend). Both are
load-bearing and both are now declared in one module, so the scanner has one
list to consult — but they have not been unified.

**Nothing pages the owner.** There is no path by which a human is woken when
the system dies. For a device-off system that is the largest remaining
operational gap, and no test can close it.

## 6. Owner actions

Three, in order of what unlocks the most:

1. **One provider credential and an authorised spend cap.** Unlocks the first
   real model call, which unlocks the cognitive loop against real providers.
2. **An isolation attestation file** (`CLAUDE_CODE_SANDBOX_ISOLATION_FILE`)
   from the runtime that enforces the network boundary. Unlocks autonomous
   engineering.
3. **Activate the scheduler** against `scripts/agent-mesh-tick.mjs` with
   `AGENT_MESH_OCCURRENCE_KEY` per delivery and zero business effects. Starts
   the clock on every duration-based tier.

Everything else the software can do for itself, defer safely, or decide from
evidence.
