# UberBond Gamechanger Mesh 24/7

Status: `PUBLIC_READ_RESEARCH_ONLY`

## Purpose

The Gamechanger Mesh removes the founder as the bottleneck for noticing high-leverage changes in technology, economics, distribution and business mechanisms.

It continuously turns public signals into:

`WORLD CHANGE -> NORMALIZED SIGNAL -> FINGERPRINT -> DEDUPE -> CORROBORATION -> COVERAGE AUDIT -> ECONOMIC/STRATEGIC SCORE -> ATTENTION STATE -> FRONTIER SIGNAL -> IDEA ATOMIZATION -> THINKER SWARM -> CAPABILITY/OPPORTUNITY TOURNAMENT`

The system does **not** claim literal whole-internet coverage. Instead it maintains an explicit coverage objective across sixteen domains and emits blind spots whenever fewer than the configured number of independent sources cover a domain.

## Source mesh

The seed registry combines direct public reads with search-agent lanes.

Direct reads are restricted to public HTTPS resources and carry only `PUBLIC_READ_ONLY` authority. Search lanes are research prompts for browser/search agents and carry only `RESEARCH_ONLY` authority.

The initial registry covers official changelogs, research feeds, open-source discovery, community signals and broad search lanes for model releases, open-model breakthroughs, agent runtimes, free-tier shifts, distribution, payments, policy, security, data/research, business mechanisms and vertical fractures.

A provider, site or source may be removed or quarantined if its terms, availability or evidence quality make continued collection inappropriate.

## Ranking law

The tournament rewards:

- novelty
- enabling power
- economic upside
- founder minutes saved
- distribution leverage
- cost-curve shifts
- cross-industry transfer
- evidence quality
- implementation ease
- time sensitivity

It penalizes:

- risk
- uncertainty
- maintenance burden
- regulatory friction
- commoditization risk

Primary/official and primary-research evidence receive higher trust than community signals. Independent corroboration improves confidence but never turns consensus into proof.

## Attention states

`IGNORE -> WATCH -> RESEARCH -> ATOMIZE -> EXPERIMENT_CANDIDATE`

An item cannot become `EXPERIMENT_CANDIDATE` on score alone. It must also meet evidence-quality and source-trust thresholds.

Even then, the mesh may only propose research/atomization/experiments. It cannot self-promote capabilities or opportunities.

## Memory law

Every observed mechanism receives a stable fingerprint. Previously seen fingerprints can be excluded from repeated escalation while retaining their evidence trail. New independent evidence can still corroborate or reopen a prior mechanism.

The target is not a firehose of articles. The target is a durable institutional memory of mechanisms, changes, failed assumptions and newly reachable capability space.

## Frontier handoff

High-ranked candidates are transformed into the existing `autonomous-frontier-intelligence` signal shape and handed to:

1. frontier signal normalization
2. idea atomization
3. Explorer/Skeptic/Economist/Engineer/Customer/Distribution/Security/Open-Source/Counterstrategy thinker swarm
4. capability or opportunity tournament
5. bounded experiment proposal when earned

The existing Frontier/Capability Genome laws remain superior to this sensor layer.

## Authority boundary

The mesh has no authority to:

- send messages
- contact prospects or customers
- purchase or subscribe
- move money
- deploy production changes
- bypass logins, paywalls, CAPTCHAs or access controls
- access private sessions
- widen its own authority
- create customer/payment/commercial truth

`PUBLIC SIGNAL != OPPORTUNITY PROOF`

`POPULARITY != ECONOMIC PROOF`

`VENDOR CLAIM != UBERBOND CAPABILITY PROOF`

`EXPERIMENT_CANDIDATE != AUTHORITY TO EXPERIMENT EXTERNALLY`

## Runtime

`npm run gamechanger:plan` builds the due-source plan without network reads.

`npm run gamechanger:tick` performs bounded public reads for direct sources, emits pending search lanes, ranks observations and writes an evidence receipt to `artifacts/gamechanger-mesh-latest.json`.

The GitHub workflow `gamechanger-mesh-hourly.yml` is scheduled hourly and uploads its evidence receipt as a workflow artifact. If hosted CI again starts zero steps, that is `INFRASTRUCTURE_NON_EVIDENCE`, not successful operation.

The native long-term target is to run the same tick through UberBond's durable scheduler/queue once founder-absence runtime closure is fully integrated.

## Closure-mode compatibility

Gamechanger discovery may continue during software closure, but it may not create feature churn. During `CLOSURE_MODE`, new discoveries are queued unless they close a demonstrated blocker, materially reduce first-cash/founder-minute risk, or supersede a current dependency with clearly stronger evidence.
