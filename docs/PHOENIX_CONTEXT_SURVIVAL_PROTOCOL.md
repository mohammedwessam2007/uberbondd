# PHOENIX Context Survival Protocol

Date: 2026-10-08. Truth class: NEW SOURCE + TESTS + CLIENT-SIDE UI, NOT AUTOMATIC CHATGPT TRANSCRIPT CAPTURE.

## Failure to eliminate

A large ChatGPT conversation becomes sluggish and eventually cannot continue. Existing UberBond Master Memory, Context Spine, Current Handoff, Wormhole and chat-import procedures preserve much of the project, but cannot prove that every **material chat-only decision** was actually saved or that a fresh chat recovered every recorded item.

## Capability

PHOENIX treats a conversation as temporary cockpit, not the durable state holder. Every material checkpoint can become a source-labeled event with a stable ID, typed truth class, exact source locator, original main SHA, optional parent-capsule digest and permanent 890-corpus identity. A recovery challenge makes the next chat account for every saved event ID and report missing events, unverified sources, chat-only assertions and moving main rather than claiming magic memory.

This is **proof of recovery of the recorded checkpoint**, not proof of recovery of the complete uncaptured ChatGPT transcript.

## Emergency iPad workflow

1. While the chat still works, ask the current agent to commit material decisions to UberBond GitHub and add a PHOENIX checkpoint. Do not wait for a UI crash.
2. If anything important is still chat-only, open your UberBond app's /phoenix.html page, enter the exact decision/result, and identify its GitHub/provenance source or CHAT_ONLY. Do not enter credentials or sensitive customer data.
3. Click Export PHOENIX file. Confirm the file reached iPad Files/Downloads. Click Copy new-chat rescue message.
4. Start a fresh ChatGPT chat within the UberBond Project. Paste the rescue message and attach the exported file if it contains unsaved material.
5. Recover GitHub main, all relevant PRs/issues and the 890 canon, then account for every capsule event. Reconcile any changed code, provider status or uncertainty. Continue from the newest verified frontier without replaying uncertain external effects.

    node scripts/phoenix-capsule-doctor.mjs reconcile private-capsule.json private-ack.json

Do not commit private owner-specific capsules or raw transcripts to a public or broadly readable repository. A conservative secret scanner is not a complete DLP engine. The local client draft and the source-typed repository capsule have deliberately distinct formats and truth boundaries.

## Limitations and next technical frontier

- ChatGPT's native UI lag, context budget, transcript access, memory and auto-archiving cannot be modified by this code.
- A user/agent must checkpoint material chat-only progress. Uncheckpointed chat content may remain inaccessible after a crash.
- Source integrity hash is not cryptographic authorship, evidence authenticity, external provider confirmation or proof of transcript completeness.
- Recovery acknowledgment source checks are *self-reported*. Provider receipts and current exact Git/production source must still be independently checked.
- Local exporter data is held in that tab until export; it is not synced across devices or durably written to backend automatically.
- Future feature candidates: authenticated private append-only Postgres capsule ledger, automatic app-owned conversation event capture, encrypted cross-device recovery, checkpoint schedule, verified fork-merging and independent source witness service. These are explicitly **NOT BUILT** in v1.

Authority remains NONE for spending, customer messages, credential changes, deployments, legal determinations or financial actions. Nothing here promotes a simulated feat, an old idea, code, or a synthetic test to real-world success.
