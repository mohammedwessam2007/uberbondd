# PHOENIX CoS Capability Operator

**Verified scope:** A Chat On Steroids Core terminal-accessible, read-only
source router plus 15 independently callable, pure first-party capability
functions. It is not a generic model agent, provider authentication system,
ChatGPT plugin install or deployed customer service.

`node scripts/phoenix-cos-operator.mjs waves`: recover all eight pinned Wave 3–10 genomes (1,560 designs) and clearly mark the original Wave 1–2 specs missing from the recovered source set.

`node scripts/phoenix-cos-operator.mjs wave 4 0 20`: browse a recovered wave by original record ID, in pages of up to 50. Each record remains source linked and research-only.

`node scripts/phoenix-cos-operator.mjs mission phoenix-wave4-0001`: compile a single original acceptance condition, immutable source pointer, donor hints, native baseline suggestions and required licensing, security, test, economics and authority gates into an actionable implementation contract. This is not the execution of the design.

`node scripts/phoenix-cos-operator.mjs status`: report active native probes,
registered reference entries and the research-only source corpus.

`node scripts/phoenix-cos-operator.mjs catalog`: list 15 source-hashed
zero-effect native capability atoms and distinguish callable wrappers.

`node scripts/phoenix-cos-operator.mjs route "strategy proof"`: recommend
already-tested local native capabilities from mission terms without granting
new permissions.

`node scripts/phoenix-cos-operator.mjs research "reliability" 5`: retrieve
source-linked entries from the 1,560-proposal PHOENIX archive without
installing or running untrusted remote suppliers.

`node scripts/phoenix-cos-operator.mjs invoke strategy.minimax-regret '{"scenarios":[{"id":"s"}],"strategies":[{"id":"hold","outcomes":{"s":1}}]}'`

`node scripts/phoenix-cos-operator.mjs invoke proof.compile '{"proofs":[{"id":"a","kind":"measurement","evidenceRef":"receipt:a","parents":[],"sourceClass":"OBSERVED","observed":true}]}'`

`node scripts/phoenix-cos-operator.mjs invoke founder.exception-prioritize '{"exceptions":[]}'`

User input must be one bounded JSON object. All other invocation atoms,
invalid JSON, arbitrary commands, large/unsafe payloads and degraded markets
are rejected. Each output contains source identity and ZERO external effects.
All 15 native source-probed capability atoms have bounded direct-input wrappers;
this does not install or authorize external suppliers. External project skill declarations and the 1,560
research hypotheses remain subject to donor identity, license, dependency,
sandbox, adversarial/holdout, economics and production authorization gates.

Chat On Steroids connects this CLI to ChatGPT within the authenticated,
already-approved Codespace. It does not automatically create a new ChatGPT
plugin or permit invoking unverified Claude/Codex subscriptions. The original
890 founder ideas and their provenance remain preserved separately.

The original Wave 1–2 specifications were not found as source-genome records; the eight pinned source genomes are numbered 3 through 10. Their absence is kept explicit, not silently reconstructed.

## Full ten-wave mission control

The recovered original design sources cover Waves 3 through 10. Exactly **1,560 source-pinned records** are available via `waves`, `wave <number> <offset> <limit>`, and `mission <original-id>`. Wave 1 and 2 individual design corpora were not recovered here, so their claimed original content is **unknown**. Eight fully recovered genomes do not establish ten fully recovered specifications.

A compiled mission is a **test-first work contract**, containing the original source pointer and canonical semantic digest, exact acceptance test, donor hints, bounded native baseline suggestions (lexical overlap only), and gating requirements for supplier license, security, dependencies, permissions, holdout benchmarks, revocation and any human action. It does **not** execute the research idea, install donors or grant model credentials. Every one of the 1,560 recovered IDs is accessible through deterministic pagination. Where implementation has not been independently audited, the status remains `NOT_VERIFIED`, not `ACTIVE` or `ABSENT`.

Try:

```sh
node scripts/phoenix-cos-operator.mjs waves
node scripts/phoenix-cos-operator.mjs wave 6 0 10
node scripts/phoenix-cos-operator.mjs mission phoenix-wave6-0001
node --test tests/phoenix-ten-wave-mission-compiler.test.mjs
```

**Important:** compiling 1,560 contracts is not implementing 1,560 software capabilities. Use existing source-verified native atoms wherever they satisfy the acceptance; build only missing mechanisms in isolated worktrees and benchmark them before promotion. Claude/Codex official sign-in is an external owner gate, not something this source-intake tool can emulate.

## Wave 3/4 native CLI attestation progress

The read-only `cli-auth` command invokes only the official `claude auth status --json` and `codex login status` commands with a bounded timeout, discards raw stdout/stderr, and emits an unsigned content-addressed state summary. Synthetic positive/negative, missing binary, timeout and secret-redaction tests run locally. Actual account login, trusted signing and successful model-backed work remain unverified. Neither CLI status command initiates sign-in or requests a model generation. Any provider network activity inside those CLIs was not independently instrumented.

## Native Wave 6 objective escrow, dependent release

The `objective-escrow-verify` CoS verb runs first-party Ed25519 objective hash verification using an independently expected signer fingerprint and a public verification key. It rejects tampered evaluator definitions even if the original signature is otherwise valid. Signing authority is **never** generated or transmitted by this gateway. The detailed, test-backed source receipt is `docs/receipts/PHOENIX_WAVE6_IMMUTABLE_OBJECTIVE_ESCROW_20261019.md`. This local proof is not a claim that actual production evaluators have a trusted pinned signing key or that all 120 Wave 6 designs were implemented.

## Wave 5 synthetic GUI replay

The local `gui-record` and `gui-replay` commands compile and run only **virtual in-memory GUI fixtures**, with stable field identity digests and no generative-model usage. Source user-entered values are hashed and not echoed. Repeatability and changed-target rejection are covered by `tests/phoenix-synthetic-gui-replay.test.mjs`. See `docs/receipts/PHOENIX_WAVE5_SYNTHETIC_GUI_REPLAY_20261019.md`. This is not a production browser agent or authorization for real clicks.

## Wave 7, Wave 8, Wave 10 proof atoms

`paper-reconcile` takes bounded JSON with `sources:[{sourceId,doi,arxiv,title,sourceRef}]`, merges compatible bibliographic source references without deleting original source records, and refuses title-only collapse across conflicting DOI identities. Its output has no external metadata verification.

`wave8-objective-guard` takes `candidateCommitSha` and a signed `objectiveEscrow` object. It blocks an altered evaluator after the declared candidate commit and **never** grants promotion by itself, even when the local objective check passes.

`source-verify` takes `{sourceText,expectedSha256,sourceRef}` and refuses changed release-note/source bytes. Caller must establish the expected digest independently. All three commands are deterministic zero-effect local checks, not remote proof or deployed product services. See `docs/receipts/PHOENIX_WAVE7_WAVE8_WAVE10_SOURCE_GUARDS_20261019.md`.
