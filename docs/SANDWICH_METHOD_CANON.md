# UberBond Sandwich Method

Status: **DRAFT BRANCH / EXECUTABLE ZERO-EFFECT SELF-COMPLETION PROTOCOL**

The Sandwich Method turns the founder's self-folding metaphor into a bounded evidence protocol.

UberBond carries two slices at once:

1. **Lower slice: exact current reality.** What is actually verified now, bound to evidence and an exact source revision.
2. **Upper slice: a stronger descendant.** A versioned target model describing a materially stronger UberBond without pretending that imagining the descendant makes it real.

The space between them is the **filling**: the negative image of missing, partial, unknown, physical, commercial, provider, founder-choice and elapsed-reality requirements.

One fold is:

`CURRENT -> STRONGER DESCENDANT MODEL -> NEGATIVE IMAGE -> HIGHEST-LEVERAGE DEPENDENCY-SATISFIED AUTHORIZED INTERNAL GAP -> BOUNDED MISSION -> INDEPENDENT VERIFICATION -> EXISTING PROMOTION AUTHORITY -> NEW CURRENT -> RECOMPUTE DESCENDANT`

Then the sandwich folds again.

## Why this exists

Ordinary roadmaps are static. They assume the author already knows what completion means.

The Sandwich Method permits the definition of a stronger UberBond to improve as UberBond learns. A later descendant may expose requirements the current system could not even name. Therefore a larger negative image is not automatically regression. Discovering previously invisible missing structure can be epistemic progress.

The method is deliberately asymmetric:

- imagination may expand quickly;
- implementation proceeds one bounded fold at a time;
- evidence, not imagination, closes a fold;
- authority never expands merely because a stronger descendant would benefit from it.

## The four objects

### Lower slice

The lower slice is the exact-current verified surface. A node may be `VERIFIED_CURRENT` only when it carries evidence references. Code existence alone is not runtime proof. Simulation is not physical proof. A plan is not customer proof. A model of a life is not an observed life outcome.

### Upper slice

The upper slice is a versioned stronger-descendant target. It has a digest, revision, statement, invariants and explicit authority class.

Target authority is one of:

- `CANONICAL_REPOSITORY`: an already-authoritative repository requirement may drive internal source/research folds.
- `FOUNDER_AUTHORIZED_PRIVATE`: an explicitly authorized private founder target may drive internal folds, but its contents must remain in private runtime/storage.
- `HYPOTHETICAL_ONLY`: the descendant may expand search space but cannot authorize implementation.

This prevents self-improvement machinery from silently inventing founder goals.

### Filling / negative image

Every target node has:

- stable id and label;
- current state: `VERIFIED_CURRENT`, `PARTIAL_CURRENT`, `MISSING` or `UNKNOWN`;
- fold class;
- dependencies;
- evidence references;
- optional mapping to canonical execution requirement ids;
- leverage;
- estimated effort;
- uncertainty.

Fold classes are:

- `INTERNAL_SOURCE`
- `INTERNAL_RESEARCH`
- `FOUNDER_CHOICE`
- `OWNED_PHYSICAL_HOST`
- `EXTERNAL_PROVIDER`
- `EXTERNAL_COMMERCIAL`
- `ELAPSED_REALITY`
- `UNKNOWN`

Only dependency-satisfied internal source/research nodes are eligible for automatic fold selection under an authoritative target.

### Fold

The next fold is the highest-ranked dependency-satisfied internal gap. Ranking rewards leverage and downstream unlocks while accounting for effort, state and uncertainty.

The fold mission binds:

- exact current source commit;
- sandwich digest;
- target digest and revision;
- exact gap id;
- fold class;
- canonical requirement mappings when available;
- independent evidence requirements;
- prohibited shortcuts.

The planner itself cannot merge, deploy, spend, message customers, move money, sign releases, mutate private goals or create physical-world proof.

## Fold outcomes

A fold may end in only five states:

- `VERIFIED`: the selected gap was independently verified under the relevant existing authority.
- `MORE_STRUCTURE_DISCOVERED`: the attempt exposed previously missing requirements or concepts.
- `BLOCKED_EXTERNAL`: evidence proves the next causal dependency genuinely lies outside source-only closure.
- `TARGET_INVALIDATED`: evidence shows the stronger-descendant model itself was wrong and must be revised.
- `FAILED`: no progress claim is made; strategy or evidence must change before retry.

Progress is counted only for the first four, and only with independent evidence.

## Sandwich progress law

> **A cycle counts as progress only if it closes a gap with independent evidence, reveals previously missing structure, invalidates a bad target, or proves a real external blocker.**

Clock ticks, repeated prompts, additional prose, self-attestation and rerunning an unchanged failed strategy do not count.

This composes with the existing Wallbreaker law:

> **SAME BLOCKER + SAME STRATEGY + NO NEW EVIDENCE = STRATEGY MUTATION.**

## Finite folds, open horizon

The terminal UberBond vision is open-ended, so the Sandwich Method must never publish a fake global completeness percentage.

It may calculate `declaredFiniteTargetCoverage` for one explicitly declared target graph. That number is local to the graph and may fall when a stronger model reveals new missing structure.

Thus:

`finite fold != final UberBond`

and

`declared target satisfied != ASI proven`

A mature self-completing system can reach a local target while simultaneously discovering that the next meaningful definition of completion is larger.

## Canonical execution bridge

When a selected gap carries `executionRequirementIds`, the Sandwich Method may map it to leaves in the exact-current canonical execution graph.

That mapping grants no execution authority.

Existing machinery remains authoritative for:

- execution-leaf continuation;
- attempt identity and retry policy;
- independent verifier attestation;
- promotion/merge;
- release signing;
- deployment;
- provider/customer/payment effects.

The Sandwich Method is the **self-completion navigation layer**, not a replacement for those controls.

## Private-founder boundary

A `FOUNDER_AUTHORIZED_PRIVATE` target may contain personal goals or life state. Such a target must not be committed to the public repository.

The CLI therefore requires private targets to be read from outside the repository and requires their full plan to be written to an explicit path outside the repository. Ordinary stdout receives only a redacted receipt.

Capability to reason from private context does not create authority to publish or transmit that context.

## The self-folding attractor

The deepest form of the protocol is:

`S(t) = exact current UberBond`

`D(t) = strongest evidence-disciplined descendant UberBond can currently model`

`G(t) = D(t) - S(t)`

Choose a dependency-satisfied internal transformation `f` with high downstream unlock value.

After independently verified promotion:

`S(t+1) = f(S(t))`

Then do **not** keep the old destination frozen.

Recompute:

`D(t+1) = stronger descendant model available to the improved system`

`G(t+1) = D(t+1) - S(t+1)`

The stronger system may see dimensions the weaker system could not.

That is the Sandwich Method: **the blueprint participates in constructing the machine, and the constructed machine earns the right to redraw the blueprint.**

## Truth boundary

This protocol is self-completion planning and evidence accounting. It does not prove global UberBond completion, ASI, physical autonomy, life outcomes, customers, revenue, provider availability, scientific discovery or any external effect.
