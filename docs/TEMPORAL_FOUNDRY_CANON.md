# UberBond Temporal Foundry Canon

## Purpose

The Temporal Foundry exists to pull useful capability from hypothetical future UberBond descendants into the present without waiting for the final future substrate.

Its governing question is:

> What function attributed to a future UberBond can be reproduced now with present evidence-backed primitives, and what smallest missing internal primitive would pull the largest additional fraction of that future function into the present?

This is **Future Raid**, **Ancestor Engineering**, and **function stealing from the future** made executable.

It extends rather than duplicates existing organs:

- **Future Selves** models possible future interpretations, regret and disagreement without giving simulated selves authority over present Mohamed.
- **GENESIS / Ontogenesis** creates possibilities, mechanisms and categories.
- **Sandwich** maintains the negative image between current UberBond and a stronger descendant.
- **Timeline Topology / Wormhole** attacks the dependency route to a chosen capability.
- **Temporal Foundry** decomposes a future-labeled capability into functions, measures how much is already present, identifies which functions are internally pullable now, and backcasts one dependency-satisfied enabling primitive for Sandwich to investigate.

## Constitutional law

**DO NOT WAIT FOR THE FINAL FUTURE IMPLEMENTATION WHEN ITS USEFUL FUNCTION CAN BE RECONSTRUCTED NOW.**

A date such as 2028, 2035 or "science fiction" is a label, not evidence that a capability requires that much elapsed time.

A future capability must be decomposed before it earns the right to remain in the future.

## Function realization states

Each decomposed function is classified separately as:

- `PRESENT_VERIFIED` — the function exists now with evidence.
- `PRESENT_COMPOSABLE` — required primitives exist now with evidence and may be composed without claiming the final future substrate exists.
- `INTERNAL_PRIMITIVE_MISSING` — the function is not present but is dependency-satisfied enough to justify a bounded internal source/research primitive.
- `EXTERNAL_OR_PHYSICAL_FLOOR` — the function currently depends on physical hardware, biology, external actors, regulation, unavailable infrastructure, or another external reality boundary, with evidence.
- `UNKNOWN` — current evidence cannot justify either availability or a causal floor.

Present and physical-floor classifications require evidence references. Source assertion alone cannot convert an unavailable physical or external function into present capability.

## Future Function Capture

The core quantity is not whether the literal final future machine exists.

It is:

`present function weight / total future function weight`

A future system may be only partially reconstructable today. Temporal Foundry deliberately preserves that distinction.

Example:

- contextual sensing may exist now;
- persistent memory may exist now;
- predictive cognition prefetch may be an internally missing primitive;
- a mature invasive neural interface may remain an external/physical floor.

UberBond should take the first three functions now rather than delay them until the fourth becomes available.

## Enabling primitive law

Temporal Foundry may select one internal enabling primitive only when:

1. the primitive is explicitly named;
2. the exact future functions it would unlock are enumerated;
3. those functions are classified `INTERNAL_PRIMITIVE_MISSING`;
4. every prerequisite of those functions is already present/composable or is included in the same bounded internal pull-forward set;
5. evidence references justify why the primitive is a serious present candidate;
6. projected future-function capture increases;
7. external, physical and unknown functions remain outside the claimed capture;
8. the terminal contract of the future capability is preserved.

The primitive is a hypothesis for implementation, not proof that the future capability has already been obtained.

## Backcasting / Ancestor Engineering

Instead of moving only forward from current UberBond, Temporal Foundry also models stronger descendants and works backward:

`hypothetical descendant -> required functions -> present functions -> missing internal functions -> smallest enabling primitive -> current engineering requirement`

The goal is to discover primitives whose creation today causes large portions of the future dependency tree to collapse toward the present.

Future descendants are design instruments, not authorities. They cannot create founder goals, rewrite sovereignty, or claim evidence that does not exist.

## Relationship to Timeline Topology

Temporal Foundry chooses **what future function to pull forward**.

Timeline Topology then asks **whether the apparent route to that exact enabling primitive can be deleted, substituted, parallelized, precomputed, represented differently, or otherwise shortened**.

For post-finite Sandwich admission, both analyses should bind to the same descendant requirement. A future-function analysis for one requirement may not be replayed beside another.

The intended chain is:

`CURRENT -> STRONGER DESCENDANT -> TEMPORAL FOUNDRY FUTURE RAID -> ONE ENABLING PRIMITIVE -> TIMELINE TOPOLOGY CHALLENGE -> TRUSTED ADMISSION -> IMPLEMENT/VERIFY/PROMOTE -> STRONGER CURRENT`

## September compression doctrine

For any capability labeled "later", UberBond should ask:

1. What useful functions are hidden inside the label?
2. Which functions already exist?
3. Which are composable from present primitives?
4. Which require only an internally buildable primitive?
5. Which genuinely depend on physical/external/biological/longitudinal reality?
6. What one primitive would pull the most additional useful function into now?
7. Can Wormhole delete or retopologize the route to that primitive?

This converts a calendar roadmap into a continuously attacked capability frontier.

## Metrics

Primary metrics:

- `presentFunctionCaptureRatio`
- `projectedFunctionCaptureRatio`
- `futureFunctionWeightPulledForward`
- `remainingExternalOrPhysicalFloorWeight`
- `remainingUnknownWeight`

A supporting strategic metric is:

`future function captured today / internal primitive introduced`

A claimed multi-year acceleration is not evidence merely because a horizon label changed. Only independently observed capability and elapsed reality can establish real-world timeline compression.

## Authority and truth boundary

Temporal Foundry has no merge, deployment, spend, messaging, credential, payment, customer, medical, legal, production or physical-world authority.

It cannot declare a biological, physical, regulatory, customer or longitudinal function complete from source or simulation.

It cannot create founder goals by imagining a future descendant.

Its job is narrower and more powerful:

**force every future-labeled capability to explain which of its functions truly require the future, and pull everything else toward the present.**
