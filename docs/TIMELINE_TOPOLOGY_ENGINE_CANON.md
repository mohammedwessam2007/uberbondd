# UberBond Timeline Topology Engine Canon

## Purpose

The Timeline Topology Engine exists to attack the duration of a route before UberBond merely optimizes the steps inside that route.

The governing question is not "How do we execute this roadmap faster?" It is:

> What dependency, representation, boundary condition, assumption, interface, ownership model, measurement method, or intermediate state makes this long route appear necessary, and what alternate topology preserves the same terminal contract with fewer or shorter causal steps?

This is UberBond's **Wormhole Engine** and **Timeline Cannibalism** protocol.

It extends, rather than duplicates, existing organs:

- **Assumption Escape** asks whether a conclusion was already fixed by the assumption set.
- **Wallbreaker** generates materially different strategy families after a wall or failure.
- **Sandwich** maintains the negative image between current UberBond and stronger descendants.
- **Timeline Topology Engine** measures the dependency route itself, identifies the critical path, distinguishes currently evidence-bound causal floors from convention, and tests whether a proposed alternate topology truly shortens the path without changing the goal.

## Constitutional law

**DO NOT OPTIMIZE THE ROUTE UNTIL YOU HAVE TRIED TO DELETE OR RETOPOLOGIZE THE ROUTE.**

A roadmap duration justified only by "this normally takes this long" is not a causal lower bound.

A claimed lower bound becomes `EVIDENCE_BOUND_CAUSAL_FLOOR` only when evidence references are attached. Even then it is a bound inside the declared graph and current evidence, not universal proof that physics makes every faster route impossible.

Only causality is allowed to make UberBond wait.

## Boundary classes

The engine can classify timeline nodes as:

- `COMPUTE`
- `INFORMATION_ARRIVAL`
- `NETWORK_PROPAGATION`
- `MATTER_TRANSFORMATION`
- `BIOLOGICAL_ADAPTATION`
- `EXTERNAL_ACTOR`
- `REGULATORY_PROCESS`
- `ELAPSED_EVIDENCE`
- `ARCHITECTURAL_CONVENTION`
- `COORDINATION_OVERHEAD`
- `REDUNDANT_WORK`
- `INTERFACE_FRICTION`
- `REPRESENTATION_LIMIT`
- `UNKNOWN`

The class is descriptive. It does not itself prove necessity.

Necessity must separately be classified as:

- `EVIDENCE_BOUND_CAUSAL_FLOOR`
- `REQUIRED_BUT_COMPRESSIBLE`
- `ASSUMPTION_ONLY`
- `UNKNOWN`

This prevents labels such as "biology" or "manufacturing" from becoming excuses for untested waiting.

## Wormhole mechanisms

The engine explicitly searches for topology changes including:

1. `DELETE_REQUIREMENT`
2. `SUBSTITUTE_TRANSFORMATION`
3. `REPRESENTATION_ESCAPE`
4. `PARALLELIZE_DEPENDENCIES`
5. `PRECOMPUTE`
6. `CACHE_OR_DISTILL`
7. `REUSE_EXISTING_CAPABILITY`
8. `PROXY_OBSERVABLE`
9. `CHANGE_BOUNDARY_CONDITIONS`
10. `INVENT_INTERMEDIATE`
11. `OUTSOURCE_EXISTING_INFRASTRUCTURE`
12. `MOVE_FUNCTION_TO_ENVIRONMENT`

The first question for a long step is therefore not "how do we make the step 20% faster?" It is "why does the step exist?"

## Terminal-contract conservation

A wormhole must preserve the terminal contract.

Changing:

`produce the same independently verified result`

into:

`produce something easier that resembles the result`

is not compression. It is goal mutation.

The engine rejects projected graphs whose objective or terminal IDs change.

## Causal-floor rebuttal

A node currently classified as `EVIDENCE_BOUND_CAUSAL_FLOOR` may still be challenged, because current evidence is not the same thing as a law of nature.

But a candidate may not silently shorten, delete, or bypass that node. It must carry explicit causal-boundary rebuttal evidence tied to the exact transformation.

Examples:

- discovering a different manufacturing process can rebut the old fabrication bound;
- discovering a valid surrogate endpoint can challenge a waiting period only if equivalence to the terminal contract is independently supported;
- a simulation cannot by itself prove that a biological, physical, regulatory, customer, or longitudinal clock was eliminated.

## Evidence states

Wormhole candidates are classified as:

- `HYPOTHESIS`
- `SIMULATION`
- `EXECUTED_INTERNAL`
- `OBSERVED_REALITY`

`EXECUTED_INTERNAL` and `OBSERVED_REALITY` compression claims require independent verification before they may count as evidence candidates.

No evidence state in this organ grants merge, deployment, spend, messaging, customer, payment, credential, DNS, production, medical, legal, or physical-world authority.

## Timeline Cannibalism search order

For every high-value critical path, UberBond should attempt, in order:

1. Delete the step before optimizing it.
2. Ask whether the terminal function can be represented differently.
3. Start all causally independent work now.
4. Precompute likely branches before information arrives.
5. Reuse, rent, or route through existing capability before constructing infrastructure.
6. Search for proxy observables that collapse waiting without laundering evidence.
7. Change boundary conditions so the obstacle stops existing.
8. Invent a new intermediate if the current ontology forces a long route.
9. Reject durations justified only by human convention.
10. Stop only at a currently evidence-bound causal floor.

## Integration with Sandwich

When the Sandwich Autocatalytic Governor is choosing the next stronger-descendant gap, it must challenge the apparent dependency path with Timeline Topology Engineering before simply adding another step to the roadmap.

A topology-changing gap should be preferred when it can plausibly remove or compress a larger amount of critical-path time than a local optimization, subject to the same novelty, dependency, falsifiability, truth, authority, and independent-verification laws.

The Wormhole Engine does not self-attest a shortcut. It changes what UberBond investigates and builds. The existing verifier and promotion surfaces remain authoritative.

## Core metric

The core measurable quantity is:

`verified critical-path time removed / wall-clock time spent discovering and validating the topology change`

Supporting measurements include:

- critical path before;
- critical path after;
- current evidence-bound floor;
- attackable critical-path time;
- total parallelizable work;
- exact nodes/edges changed;
- mechanism class;
- evidence class;
- terminal-contract preservation;
- independent-verification state.

## Final law

> Everything that can happen now should happen now. Everything causally independent should run in parallel. Everything predictable should be precomputed. Everything inherited from convention should be challenged. Everything that truly requires the future must carry evidence for why the future is required.

UberBond does not merely travel through its roadmap faster.

**UberBond searches for ways to make sections of the roadmap cease to exist.**
