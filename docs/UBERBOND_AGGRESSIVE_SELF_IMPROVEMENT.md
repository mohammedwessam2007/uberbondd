# UberBond Aggressive Self-Improvement Mode

Status: implementation contract for the post-#400 runtime.

## Objective

Drive the highest-value internally solvable engineering improvement as soon as evidence makes it actionable, while preserving exact-source truth, owner sovereignty, and zero accidental real-world authority.

This is not a permission expansion. It is a latency, search-pressure and recovery-throughput expansion.

## Operating cadence

- Whole-brain Gamechanger / GENESIS / capability / compute / metacognitive sensing: twice per hour.
- Trusted self-maintainer pulse: four times per hour.
- Each maintainer run may perform up to three bounded result-pickup attempts, separated by two minutes, so a worker result can be admitted and verified during the same workflow instead of waiting for the next pulse.
- The issue-driven relay worker still wakes immediately for a real relay task. Its missed-event / abandoned-lease safety net now runs every five minutes instead of hourly and drains at most three tasks per invocation.
- Concurrency remains serialized. A long verification run is never overlapped by a second maintainer mutation run or a second relay worker.
- Maintenance identity remains bound to the exact main SHA, so repeated pulses on unchanged source reuse the same mission instead of spraying duplicate work.

## Aggression means

1. search more often for the highest-leverage internal defect, bottleneck, capability gap or architectural local maximum;
2. feed newer Gamechanger, GENESIS, Feature Genome, Synaptic Map, Capability Genome, Compute Sovereignty and self-maintenance evidence into prioritization;
3. reduce idle time between worker completion and trusted verification;
4. recover missed relay events and abandoned worker leases within minutes rather than leaving an hour-long dead zone;
5. drain a small bounded backlog without creating unbounded agent loops;
6. keep trying after source revision advances, so every accepted improvement creates a fresh search frontier;
7. preserve failures as evidence and route them back into Wallbreaker / MAX / metacognition rather than blindly repeating the same mechanism.

## What aggression never means

- no self-granted merge, deployment, customer, payment, DNS, credential or spend authority;
- no outbound contact merely because maintenance is frequent;
- no test weakening, evidence laundering or readiness inflation;
- no covert persistence or hidden owner override;
- no quota evasion, identity farming, stolen credentials or billing bypass;
- no conversion of model agreement into external or economic truth.

## 100% definition

`100%` is a moving internal closure denominator, not a claim of final intelligence. At any measurement point, UberBond is internally 100% only when every then-known internally solvable P0/P1/P2 is closed, superseded by a stronger verified implementation, or proven non-blocking on the exact final source head. External proof, owner-authority, provider/configuration and elapsed-time gates remain explicitly outside that denominator.

After an exact head earns 100%, the aggressive loop deliberately searches for a new denominator by discovering previously unknown weaknesses and useful capability gaps. Reaching 100% therefore triggers another search frontier rather than freezing the organism.
