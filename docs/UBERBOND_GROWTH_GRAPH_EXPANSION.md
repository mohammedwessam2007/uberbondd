# UberBond Growth Graph Expansion

## Purpose

Persist the 2026-08-29 distribution expansion so future chats do not reconstruct separate "clone" ideas from scratch.

UberBond should absorb the useful mechanisms from Clay, Braze/Customer.io, social distribution suites, technical SEO systems, and video/content generators into one governed Growth Graph.

## Unified loop

`world/account signal -> public/licensed evidence -> enrichment waterfall -> identity/fit -> offer -> partner/journey/outbound/owned-content motion -> touch/exposure -> response -> qualification -> cleared payment -> delivery -> customer acceptance -> renewal/expansion -> cost/founder minutes -> cleared contribution -> learning`

## 1. Clay-class evidence waterfall

Current status: core exists. `budgeted-enrichment-waterfall`, prospect enrichment planning/budget, provenance, evidence reconciliation and qualification already supply the control-plane skeleton.

Next gap is not another clone. It is authenticated provider adapters, caching, provider receipts, cost/coverage/accuracy measurement and routing based on downstream economic evidence.

## 2. Enterprise journey orchestration

Current status: bounded compiler merged in PR #194.

Use Braze/Customer.io mechanisms such as event triggers, audience/profile state, delays, conditions, experiments, message frequency limits, configured webhooks, multi-channel actions and conversion goals. Execution must compose the canonical durable scheduler and omnichannel communication contract.

## 3. Sender Infrastructure Mesh

Current status: safe allocator merged in PR #194.

Use multiple truthful authenticated sending domains/IP pools for traffic-class isolation, healthy capacity, gradual warm-up, maintenance/failover and reputation management. Never use domain/IP churn to evade blocks, poor reputation, complaints, quotas, suppression or platform enforcement.

## 4. Social distribution

Current status: canonical social-publication scheduling already exists; provider-specific adapters remain.

Prefer official/authorized APIs and current platform policies. Do not use scraping/browser bots to automate LinkedIn connection requests, DMs, likes, comments or other prohibited behavior. Unsupported consequential actions become human/provider handoffs rather than browser evasion.

## 5. Evidence-to-content engine

Current status: source-bound content-pack compiler on this branch.

One evidence set can create preparation tasks for SEO/AEO briefs, technical SEO remediation, LinkedIn/social briefs, video scripts, partner sales assets and outbound insights. Every factual claim remains traceable to supplied evidence and no output auto-publishes.

## 6. Technical SEO

Do not clone a generic 170-check crawler merely because competitors have one. Reuse browser/web evidence capability and add only diagnostics that support current buyer/offer paths. Separate observed technical evidence from remediation recommendations and never claim ranking/traffic outcomes before measurement.

## Distribution priority

For the current first-money path, preserve:

1. partner/white-label;
2. product-led evidence/diagnostic;
3. owned evidence content and AEO/SEO;
4. governed direct outbound after activation gates;
5. referral/expansion after accepted customers;
6. paid media only after measured positive economics.

## Economic rule

The target is not maximum reach or message volume. The Growth Graph ultimately reallocates by trusted `cleared contribution / founder minute` while respecting legal, provider-policy, suppression, consent, sender-health, authority and evidence constraints.
