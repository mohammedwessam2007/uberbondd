# UberBond Master Memory

## Why this file exists

UberBond is larger than a single context window. Conversation resets, model changes, shared-chat links, and coding-session compaction must never collapse the company into the most recent offer or branch. This file is the human-readable long-horizon memory layer. `artifacts/uberbond-memory-index.json` is the machine-readable companion.

This memory is **not present-tense commercial truth**. Current `main`, exact executable receipts, current readiness artifacts, and durable provider/customer/payment/delivery evidence outrank it. The purpose here is anti-forgetting, not claim promotion.

## Final goal

UberBond's north star is **risk-adjusted cleared contribution profit per founder minute**. The intended end state is a private, cloud-runnable, globally distributed economic operating system that can lawfully discover opportunities, understand their mechanisms, select and compose offers, obtain distribution, execute bounded work, collect and reconcile payment, prove delivery and customer acceptance, renew/expand, learn from verified outcomes, acquire missing capabilities, and increasingly operate while the founder is absent.

The ambition may be enormous. The truth law stays boring on purpose: architecture is not revenue, a lead is not money, an invoice is not cleared payment, payment is not accepted delivery, and a first payment is not renewal.

UberBond's durable doctrine is **many front-end offers, one shared operating system**. A single active experiment is a portfolio-allocation discipline, not a redefinition of the company.
