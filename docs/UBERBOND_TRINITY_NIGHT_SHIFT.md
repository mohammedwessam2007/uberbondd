# UberBond Trinity Night Shift

## Purpose

Coordinate three parallel intelligence/build lanes without duplicating architectures or corrupting current truth.

This document is coordination law, not permission to fabricate revenue, customer acceptance, provider state, or elapsed unattended proof.

## North star

Build UberBond toward a private, globally runnable, cloud-operated, evidence-first economic operating system that can discover opportunity, research markets, assemble many offers from shared primitives, choose distribution, execute bounded commercial workflows, collect/reconcile real payment, deliver accepted work, renew/expand, learn from verified economics, acquire missing capabilities, and reduce founder minutes.

Primary optimization target:

`risk-adjusted cleared contribution profit / founder minute`

Massive wealth is an ambition, not a repository fact or forecast.

## Shared truth

All lanes begin by refreshing current `main`, running `npm run brain`, and reading repository canon. Current code and executable receipts outrank this document.

Never build a second UberBond architecture because another lane is busy.

Before any consequential write:

1. refresh `main`;
2. inspect open/recent PRs/issues/branches;
3. search for equivalent current modules;
4. declare the lane/branch/mission in a durable issue or PR;
5. dedupe and reuse stronger concurrent work;
6. write only the smallest dependency-complete delta.

## Merge protocol

The phrase “merge everything” means:

**merge every useful, compatible, verified piece of work that strengthens current main.**

It does not mean force-merge stale donor branches.

For every historical branch/PR classify:

- already represented;
- cleanly mergeable;
- selectively cherry-pickable;
- semantic donor only;
- obsolete;
- dangerous/incompatible.

Extract valuable tests/invariants/algorithms even from obsolete donors.

- exact files/artifacts changed;

## Termination rule

Continue until no material dependency-satisfied internal mission remains for the lane.

Then classify remaining blockers as external proof, credentials/identity, legal/tax authority, customer reality, spend authorization, provider activation or elapsed-time proof.
