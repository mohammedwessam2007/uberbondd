### Authority plane

Delegation is attenuation-only. Child scopes/effects cannot exceed the parent. Revocation invalidates descendants. A component's capability never grants consequence authority.

### Provenance plane

Every admitted package/build artifact must bind name, version, source reference, SHA-256 source identity, license, build-recipe identity, capabilities, permissions and network destinations. Permission/network widening triggers fresh review.

### Transactional state

Every meaningful system mutation follows:

`current -> candidate -> isolated verification -> promotable -> atomic promotion -> health observation -> retain OR rollback`

A model may propose a candidate. It may not manufacture verification or self-grant deployment authority.

### Unknown-unknown lab

The OS deliberately attacks assumptions that ordinary systems tend to treat as invisible background conditions: clocks, storage acknowledgement, network identity, memory availability, authority persistence, model availability, boot integrity, heterogeneous compute, dependency persistence, power around commit boundaries, filesystem writability and entropy availability.

Unknown-unknown reasoning is experimental discipline, not mysticism. A surfaced anomaly becomes a question or experiment. Independent cross-source resistance, declared negative-space expectations and concept pressure feed UberBond's existing unknown-unknown/Ontogenesis machinery.

### Kernel neutrality

Linux starts as the preferred bootstrap supplier because it is mature, inspectable and broadly supported. UBER/OS tracks the capabilities it receives from Linux and keeps those capabilities behind explicit contracts. Future microVM or independent kernels must win by evidence.
