```text
Make the relay say what it is doing

The GitHub issue list cannot answer "is the relay working?". An issue
labelled agent-relay:claimed looks identical whether a worker is mid-run or
died an hour ago holding the lease. A queue with nothing running looks
identical to a queue being worked. Those need opposite responses.

summarizeRelayQueue() separates the four states that actually differ:

  IDLE      nothing to do
  ACTIVE    work waiting or in flight, someone is on it
  STALLED   work waiting and nothing running. Not broken -- nobody is home,
            which is the easiest failure to mistake for a crash.
  STRANDED  a worker claimed a task and vanished. The lease lapsed so the task
            is claimable again, but work may have been done and thrown away
            and nothing announces that.

STRANDED outranks STALLED deliberately: idle means nobody started, stranded
means someone started and disappeared.

It is a pure function over issues, comments and `now`, so it is testable
without a network and cannot drift from what the transport reports.
scripts/relay-status.mjs is a thin read-only wrapper that exits 1 on
STRANDED or STALLED, so it can gate a check without anyone parsing output.

Proved against real GitHub, not fixtures: opened issue #50, claimed it with a
one-second lease so it would strand immediately, and the report caught it.
That run exposed a gap worth more than the feature -- it printed "last held
by null", because resolveLease() threw away the claimant once a lease
expired. For a stranded task that is the single fact you need: which worker
vanished. lastHolder and lapsedAt are now preserved. holder stays null,
because nobody holds an expired lease and existing callers branch on that, so
the new fields cannot change any current decision.

Issue #50 is closed with an explanation of why it existed.
```
