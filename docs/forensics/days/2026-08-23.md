```text
Give the six secret scanners one vocabulary, and stop receipts quoting credentials

across every tracked file.
```

```text
Stop a bounded scan answering with a stale run, and soak the spine

The soak drove 800 scheduler occurrences and 60 autonomy runs through the
durable spine and found a run that simply stopped. Not failed -- stopped, with
every reload returning ok and an older snapshot.

Every read in the autonomy store pulls a bounded window of audit rows and
picks the newest match out of it. Once that window comes back full, "no
matching row" stops meaning "no such run" and starts meaning "the run may be
past the bound", and from inside the function those are the same observation.
So the reload handed back the last snapshot it could see and the caller had no
way to tell a stalled run from a healthy one.

A saturated window is now its own reported failure rather than an answer, and
a write that cannot see its own history refuses instead of risking a sequence
regression. A stalled run that says it is stalled can be fixed.

This is a bound, not a cure: the window is fixed at 2000 snapshot rows because
the store's filters match top-level columns and cannot select on detail.runId.
Per-run reads need a schema change, and that is recorded rather than pretended
away.

The soak stays as a gate: one occurrence means exactly one terminal receipt
however many times it is delivered, every run reaches a terminal state, no
completed run reappears as active, and durable growth is linear in work done.
```
