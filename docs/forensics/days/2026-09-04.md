```text
Make the mutation war survive being interrupted

The full war takes over an hour against a real database, and this host restarts
its container under load. Four consecutive runs were killed in flight, each one
discarding every verdict it had already earned, so the summary line the
readiness artifact quotes had never once been produced for the current registry.
Restarting it hopefully a fifth time is not a plan.

MUTATION_WAR_JOURNAL appends each verdict the moment it is decided and replays
it on the next run, so an interrupted war resumes instead of starting over.
Replayed rows are labelled in the output; a run that says KILLED should be able
to say whether it watched that happen.

A resumable gate is also a gate that can report work nobody did, so the binding
is the feature rather than a detail. Every entry carries a hash of the mutation
that earned it -- file, anchor, replacement and killing suites. Move any of
them and the entry stops matching and the mutation runs again, because a verdict
is about a specific guard in a specific place, not about an id. Suite order is
deliberately not part of it: a cosmetic reordering should not discard an hour of
real evidence, or the resume is one nobody uses.

Five tests hold this down, because its failure mode is a green summary line
rather than a red one, and a green lie is not something a later run corrects:
an id alone cannot claim a verdict, a wrong or absent fingerprint is refused, a
damaged journal loses entries rather than inventing them, a missing journal is
empty rather than an error, and a later verdict supersedes an earlier one in
both directions -- a SURVIVED recorded after a KILLED must stick, or the record
can only ever improve. JOURNAL-01 and JOURNAL-02 confirm both halves are killed
when weakened.
```

```text
Bound the mutation war's suites, and stop journaling skips

Two defects, both found by the war stalling in front of me.

**No suite deadline.** The war ran each killing suite with no timeout, so one
suite that never returned left the whole run in ep_poll with no output, no
verdict, and nothing to say which mutation it was on -- thirteen minutes of a
run went that way before anyone read /proc. A real database makes that hang
reachable, which the postgres-real runner already found the hard way; the war
never got the same repair.

Each test is now bounded at 120s so most hangs surface as an ordinary failure,
with a 600s wall deadline as the backstop for a suite wedged before the runner
starts counting. A killed suite gets its own verdict: SUITE_TIMED_OUT, which
lands in "not tested at all" and fails the run rather than being absorbed into

otherwise read as a mutant that died when nothing finished.

no longer exists and quietly stop testing that guard for good -- the same shape
as the CRAWL-01 problem the browser resolver was written to end, arriving
through the mechanism built to fix it.

The rule lives in appendVerdict rather than at the call site, because it is the
journal's invariant and a caller that forgets it should not be able to write
one. Everything else survives, including the bad news: SURVIVED, SUITE_TIMED_OUT
and ANCHOR_AMBIGUOUS are all remembered, or the record could only ever improve.

TIMEOUT-01 and JOURNAL-03 kill both. JOURNAL-03's anchor had to move into
```

```text
Break the hang cascade, and take one bounded second look at a hang

Three guards -- HYG-01, HYG-02, MONEY-17 -- kept reporting SUITE_TIMED_OUT in a
full run and KILLED alone. The failing set drifted later each run, which is the
signature of a cascade rather than three unreliable tests.

A suite killed at its deadline can leave a PostgreSQL backend that never notices
its client is gone: the stall the postgres-real runner already documents. Each
one holds a connection and keeps working, so the first hang in a run makes the
next one likelier. Those clients are provably gone -- the runner killed the
process that opened them -- so they are terminated before each database-backed
mutation, reclaiming the connection rather than interrupting live work.

With the cascade cut, a hang can still happen, and a guard that was never tested
is the one thing this file must not leave standing. So a SUITE_TIMED_OUT gets
one second attempt, against the reclaimed state rather than as a repeat of an
unchanged mechanism.

This is deliberately not "retry until it passes":
- only a hang qualifies, because that is the verdict meaning no measurement was
  taken. A SURVIVED or a KILLED is a measurement and stands on the first run.
- exactly one attempt, no loop.
- whatever it finds is recorded, including another hang.
- the row is printed as "(second attempt after a hang)", so it can never be read
  as a clean first pass.

A test asserts that shape rather than leaving it to review, because a retry loop
is how a mutation gate quietly stops meaning anything.
```
