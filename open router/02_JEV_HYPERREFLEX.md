# 02 — Jev Hyperreflex

## Role

Jev is the semantic control plane, not the sovereign reasoner.

~~~
Exact logic -> code
Bounded fuzzy judgment -> Jev
Generative search -> cheap model swarm
Novel irreducible reasoning -> Frontier Crown
~~~

## Core economic idea

Prefer one shared state with many typed Noul / Choice / Score questions over repeated generative LLM calls that re-ingest the same state.

## Jev Decision Tensor

For each live mission, compile typed semantic signals such as:

- novelty;
- uncertainty;
- evidence sufficiency;
- contradiction severity;
- materiality;
- reversibility;
- stakes;
- branch viability;
- additional-search value;
- worker disagreement;
- model suitability;
- context relevance;
- cache candidate equivalence;
- Crown necessity;
- drift likelihood;
- applicability-domain confidence.

These signals drive orchestration but do not manufacture proof.

## Hyperreflex uses

Routing:
- Which worker lineage should wake?
- Is a specialist warranted?
- Is another branch useful?
- Is Crown interruption required?

Evidence:
- Is E17 relevant to C4?
- Does E12 materially contradict C9?
- Is evidence sufficient to stop searching?
- Is a source genuinely independent?

Adversarial synthesis:
- Which claim remains disputed?
- Which minority hypothesis survives?
- Which attack changes the answer if true?
- Which branch is dominated?

Context:
- Which artifact should load?
- Which source slice is likely relevant?
- Which state can remain referenced?

Low Jev relevance is a loading priority, never permission to delete unique information.

Monitoring:
- Has distribution drifted?
- Is a certified circuit seeing out-of-domain state?
- Does a result need Crown audit?
- Has model/provider behavior materially changed?

## Applicability Passport

Every promoted Jev circuit carries:
- circuit ID;
- semantic purpose;
- task archetype;
- valid input domain;
- excluded states;
- Crown reference model/revision;
- evidence date;
- paired holdout count;
- paired regressions;
- false-positive/false-negative evidence;
- calibration evidence;
- source dependencies;
- freshness TTL;
- drift triggers;
- audit rate;
- decompile action;
- certificate pointer.

If a required passport field is stale or violated, the circuit loses authority.

## Frontier-to-Jev compiler

After every expensive Crown result ask:

1. What was genuinely novel?
2. Which bounded choices were made?
3. Which facts controlled those choices?
4. Which conditions would reverse the decision?
5. Can the fuzzy boundary become Noul/Choice/Score?
6. Can exact portions become deterministic code?
7. What fresh holdouts would falsify the circuit?
8. What drift signal should reawaken the Crown?

The output is a SHADOW candidate, not automatic authority.

## Promotion ladder

~~~
PROPOSED
 -> SHADOW
 -> PAIRED EVALUATION
 -> ZERO-LOSS CANDIDATE
 -> CANONICAL CERTIFICATE
 -> BOUNDED REFLEX
 -> DETERMINISTIC COMPILATION CANDIDATE
 -> CODE
~~~

Any material regression:

~~~
FREEZE -> DECOMPILE -> CROWN -> REVALIDATE
~~~

Jev may freely trigger more review. Suppressing required Crown review is allowed only inside explicitly certified routing domains.

## Main KPI

~~~
frontier calls avoided by certified Jev
---------------------------------------
              Jev dollar
~~~

Jev succeeds when it makes expensive brains sleep safely.
