## Reference-cost accounting

Every completed important task should have two costs.

### Actual UberMind cost

```
actual_all_in_cost =
  Jev
+ cheap workers
+ Crown
+ second Crown
+ model/provider fees
+ paid tools
+ retrieval/search charges
+ relevant cloud marginal costs
```

### Reference cost equivalent

The measured or conservatively reconstructed cost for the strongest verified frontier baseline to perform matched work directly.

Do not fabricate reference cost when it is not observed.

## Compression factor

```
compression_factor =
  reference_cost_equivalent
  /
  actual_all_in_cost
```

A result counts only when UberMind finished-work quality is equal or better on the required dimensions.

Cheap-but-worse produces no valid compression win.

## Crown spend minimization

Attack all multiplicative terms:

```
frontier cost
=
number_of_calls
x fresh_input_per_call
x output/reasoning_per_call
x effective_price
```

Reduce:

- call count with reuse, multicast, coalescing, Jev, decision DAGs;
- fresh input with exact references, prefix caches, diffs, semantic dependency pruning;
- output with structured verdicts and patches;
- effective price with same-model provider competition, Batch/deferred modes, verified cache rates, and direct-provider arbitrage where superior.

Quality may not be reduced to improve any term.

## Crown-call coalescing economics

Suppose five agents each need the same unresolved proposition.

Naive:

```
5 x Crown call
```

Preferred:

```
1 x Crown call
+ 1 decision artifact
+ 5 consumers
```

Metric:

```
multicast_factor =
  downstream_decisions_resolved
  /
  Crown_calls
```

## Crown Thought Capital ROI

For each expensive call:

```
lifetime_return =
  direct_reference_cost_avoided
+ future_Crown_calls_avoided
+ reused_task_value
- call_cost
- maintenance_cost
- revalidation_cost
```

A high-ROI Crown call discovers a reusable semantic circuit or deterministic invariant.

## Negative Knowledge ROI

Track how often stored failure knowledge prevents:

- repeated dead-end searches;
- repeated broken tool paths;
- repeated unsupported claims;
- repeated poor model selection;
- repeated bad prompt topology.

Negative knowledge should expire when its assumptions expire.

## Empirical success definition

The program is succeeding when:

1. final quality does not regress against the current strongest verified baseline on the evaluated task class;
2. actual all-in cost is materially lower;
3. repeated work shifts from Crown to certified Jev/code;
4. the compression factor rises over time;
5. founder effort falls;
6. a new stronger Crown can be adopted without architecture rewrite.

## What would falsify the $30 dream

Examples:

- hard real workload consistently requires large irreducible Crown reasoning;
- cheap workers add little useful information;
- Jev cannot safely absorb meaningful recurring decisions;
- cache locality is weak;
- decision reuse is low;
- frontier pricing rises faster than compression;
- latency/queue constraints become unacceptable;
- zero-loss certification rarely generalizes.

If reality shows this, budget must rise.

The quality target does not fall.
