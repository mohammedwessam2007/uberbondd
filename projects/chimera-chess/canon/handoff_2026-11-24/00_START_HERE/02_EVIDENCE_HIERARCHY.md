# Evidence hierarchy
1. A file present in the handoff ZIP with matching SHA-256 establishes the bytes included here, not whether an experiment reported inside it is scientifically correct.
2. A clean-extraction logfile is source-supplied evidence of a run, not an independently rerun command in this new runtime.
3. User-quoted Codex message is a claim attributed to Codex; the raw V6 PGNs, weights and executable are not included.
4. Historical design plans are objectives and hypotheses, never implementation receipts.
5. The canonical 167-ID dossier is preserved as provided; historical anti-detection proposals are archived only, not operational mandates.
6. Do not infer source content or completed code from a named link or a prior ZIP that contains only prompts.
7. `01_CANON` plus `02_CODEX_PHASE1_EVIDENCE` plus `03_V6_CODEX_EVIDENCE` should be inspected before proceeding. The latest ledger isn't provided, so the Phase1 CSV cannot be quietly relabeled V6.
